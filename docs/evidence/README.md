# Project records used in this case study

The runnable demo can show how the website behaves now. It cannot reproduce the original delivery dates, event traffic, account billing or Search Console reports. This directory keeps cleaned-up copies of those project records without exposing client or account details.

| Record | What it covers | What is left out |
| --- | --- | --- |
| [Delivery timeline](delivery-timeline/) | Milestones from the first reviewable MVP through launch, event operation and the later metrics review | Private messages, identities, quotations, attachments and unsupported productivity or business-impact claims |
| [Production metrics](production-metrics/) | Event-window traffic, runtime usage, shared-account billing position and the direct first-year domain cost | Identifiers, personal data, raw submissions, payment details and project allocation that the source cannot show |
| [Search discoverability](search-discoverability/) | Captured production `robots.txt`, bilingual sitemap behaviour and sanitised verified Search Console outcomes | Account identity, screenshots, permission listings and raw low-volume query data |

Each record states when it was captured, where it came from and what it cannot show. These files are not credentials, operational backups or a replacement for the private project record.
